# Rule: 코드 주석 가이드라인

## 1. 핵심 원칙
* **코드가 곧 설명입니다:** 주석을 써야 이해되는 코드라면, 먼저 변수와 함수 이름을 더 직관적으로 바꾸세요.
* **'왜'만 남깁니다:** 코드가 '무엇(What)'을 하는지는 이미 코드가 보여줍니다. 왜(Why) 이렇게 작성해야만 했는지 맥락만 전하세요.
* **가장 쉬운 언어를 씁니다:** 어렵거나 복잡한 용어 대신, 누구나 읽자마자 바로 이해할 수 있는 명확한 단어를 사용하세요.
* **군더더기를 뺍니다:** 단 한 줄이라도 더 줄일 수 있다면 망설이지 말고 줄이세요.

---

## 2. 절대로 쓰지 않는 주석 (Forbidden)

### 2.1. 코드를 그대로 읽어주는 주석
코드를 읽으면 바로 알 수 있는 내용을 한국어로 다시 번역하지 마세요.

```typescript
// BAD: 코드를 그대로 읽어주는 의미 없는 주석
const user = await fetchUser(userId); // 유저 정보를 가져옵니다.
if (!isLoggedIn) return; // 로그인되어 있지 않으면 종료합니다.
```

### 2.2. 설명조의 AI 사족
작업 과정이나 목적을 친절하게 설명하는 듯한 서술형 주석은 남기지 마세요.

```typescript
// BAD: 서술형/설명형 사족
// 에러가 발생하는 것을 방지하기 위해 예외 처리를 추가해 두었습니다.
```

### 2.3. Git이 알고 있는 정보
작성자, 작성일, 수정 이력 등은 Commit History로 관리합니다.

```typescript
// BAD: 헤더 및 히스토리 주석
/**
 * 작성자: 개발자
 * 내용: 결제 연동 로직 수정
 */
```

### 2.4. 주석으로 숨겨둔 코드 (Dead Code)
안 쓰는 코드는 주석 처리하지 말고 바로 지우세요. Git으로 언제든 되돌릴 수 있습니다.

---

## 3. 작성해야 하는 주석 (Allowed)

주석은 오직 **'비직관적인 이유'**나 **'숨겨진 맥락'**을 전달할 때만 씁니다.

### 3.1. 비즈니스 맥락 및 정책 제약
코드만 보고는 파악하기 어려운 실제 서비스 정책이나 제약을 밝힙니다.

```typescript
// GOOD: 이유와 맥락이 명확한 주석
// 야간 점검 시간(23:50 ~ 00:10)에는 결제 승인 요청을 대기 상태로 전환합니다.
```

### 3.2. 버그 회피 및 우회 로직 (Workaround)
외부 라이브러리나 특정 환경 문제로 불가피하게 우회한 이유를 적습니다.

```typescript
// GOOD: 특수한 처리 이유 전달
// iOS Safari 환경에서 스크롤이 튀는 현상을 막기 위해 repaint를 강제로 유도합니다.
```

---

## 4. Claude CLI 실행 규칙
1. **기본값은 '주석 없음(Zero Comments)'입니다.** Section 3의 명확한 이유가 없다면 주석을 단 한 줄도 작성하지 마세요.
2. **출력 전 검토:** 코드를 출력하기 전, 불필요하거나 자명한 주석이 남아있지 않은지 확인하고 모두 제거하세요.
