## 2. 배경 (사건 기록)

청약 공고 목록(SUBS-01, figma 135:5601)의 **필터 바가 Figma에서는 가로 1줄**인데, 구현이 세로 3~4줄로 렌더되는 문제가 **여러 차례 수정 후에도 "여전히 3줄"로 반복** 보고되었다.

실제 원인은 두 겹이었다.
1. 코드는 이미 단일 행(`flex items-center` nowrap)으로 수정됐으나, **사용자가 보던 화면은 옛 dev 서버(포트 3000)** 였다. 새 서버는 포트 충돌로 3001에 떠 있었다(`⚠ Port 3000 is in use, trying 3001`).
2. 수정 검증을 `typecheck`/`lint`/`build` 통과로만 갈음하고 **실제 렌더를 눈으로 확인하지 않았다.**

이 문서는 위 재발을 막기 위한 절대 규칙과 실행 절차를 정의한다.

## 3. 근본 원인

| # | 원인 | 설명 |
|---|------|------|
| C1 | **시각 미검증** | `typecheck`/`lint`/`build` 통과는 컴파일·타입 정합만 보장한다. **레이아웃·간격·정렬 등 시각 정합은 보장하지 않는다.** 완료 판단을 정적 검사로 갈음하면 시각 불일치를 놓친다. |
| C2 | **stale dev 서버 / 포트 혼선** | 기존 dev 서버가 살아 있어 새 코드가 다른 포트로 떴다. 사용자·에이전트가 **옛 서버(옛 코드)** 를 보며 "고쳐지지 않았다"고 오인. |
| C3 | **브랜치 분산** | 수정을 미병합 별도 브랜치에 두어, 사용자가 실제 보는 브랜치/빌드에는 반영되지 않았다. |
| C4 | **Figma 부분 판독** | 초기 구현 시 오토레이아웃 모드(row/column)를 부분만 읽어 세로 스택으로 오해했다. |

## 4. 절대 규칙 (V1~V5) — 위반 시 멈추고 보고

| # | 규칙 |
|---|------|
| **V1** | **시각 검증 없이 "완료" 금지.** Figma 화면/컴포넌트를 구현·수정하면 **실제 앱을 실행해 렌더를 확인**한 뒤에만 완료로 보고한다. 확인 수단: ① 브라우저 스크린샷(우선), ② 최소한 dev 서버 서빙 DOM을 `curl`로 받아 핵심 클래스/구조를 Figma와 대조. `typecheck`/`build` 통과만으로 완료 판단 금지(C1). |
| **V2** | **단일 dev 서버.** 실행 전 기존 서버 종료 여부·포트를 확인한다. `⚠ Port … in use` 경고가 뜨면 **다른 포트로 우회하지 말고 기존 서버부터 정리**한 뒤 지정 포트(3000)로 재기동한다. 여러 서버 동시 기동 금지(C2). |
| **V3** | **사용자 확인 경로 일치.** 수정은 사용자가 실제 보는 **브랜치/빌드에 반영**되게 한다. 보고 시 **어느 브랜치·서버·포트에서 검증했는지 명시**한다. 한 화면 = 단일 브랜치 유지(C3). |
| **V4** | **Figma 전수 판독.** 구현 전 대상 노드의 **오토레이아웃(mode row/column·gap·padding·정렬·sizing)·타이포·색·radius·상태**를 전 요소 판독한다. 스크린샷 시각 대조를 병행한다(C4, figma-implementation-rule D1/D5). |
| **V5** | **변경 후 재검증.** 코드 수정 시 dev/build를 **재기동**하고 브라우저는 **하드 리프레시**(캐시 무효화)로 반영을 확인한 뒤 재판단한다. |

## 5. 실행 절차 (체크리스트)

Figma 기반 화면/컴포넌트 구현·수정 시 순서대로 수행한다.

1. [ ] **서버 정리**: 실행 중 dev 서버·점유 포트 확인, 잔존 서버 종료.
2. [ ] **Figma 전수 판독**(V4): 오토레이아웃 모드·gap·padding·정렬·sizing·색·타이포·radius·상태.
3. [ ] **구현**: 디자인 토큰·공용 컴포넌트 사용(하드코딩 0).
4. [ ] **정적 검사**: `typecheck` / `lint` / `build`.
5. [ ] **실행 & 시각 검증**(V1): dev(단일·지정 포트) 실행 → 대상 경로 렌더 확인. 스크린샷 또는 `curl`로 서빙 DOM 핵심 구조/클래스 대조.
6. [ ] **Figma 시각 대조**: 구현 렌더 vs Figma 스크린샷(임의 추가/변경 없음).
7. [ ] **보고**(V3): 검증한 브랜치·포트·결과와 미반영/후속 사항을 명시.

---

## 6. 도구

- **브라우저 스크린샷 도구 미설치 상태**에서는 최소 검증으로 dev 서버 + `curl`로 서빙 HTML을 받아 핵심 클래스(레이아웃 방향·radius·활성 색 등)를 Figma와 대조한다.
- 픽셀 단위 시각 대조가 필요하면 브라우저 자동화(Playwright 등)를 도입하거나, 실행 절차를 **프로젝트 run 스킬**로 캡처한다(`/run-skill-generator`).
