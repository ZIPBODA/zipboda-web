## 2. 서비스와 현재 작업 범위

집보다는 공공 청약 탐색, 주거 공간 확인, 인테리어 콘텐츠, 가구 쇼핑을 연결하는 주거 서비스다. [GitHub 조직 소개](https://github.com/ZIPBODA)는 3D·AR·쇼핑·커뮤니티까지 전체 비전을 설명한다. 소개에 나오는 기능을 현재 웹의 구현 완료 또는 현재 작업 범위로 간주하지 않는다.

**2026-09-17 사용자 지시: 현재는 PC·Mobile 반응형 웹 작업만 진행한다.** 기존 쇼핑 화면도 반응형 검토 대상이지만, 결제·백엔드·네이티브 앱의 신규 구현은 별도 요청 범위다.

| 저장소 | 역할과 확인 근거 |
|--------|------------------|
| `zipboda-web` | 현재 작업 저장소. 사용자 반응형 웹과 대표 정의서 보관. 로컬 코드 및 공개 저장소 확인 |
| `zipboda-app` | 별도 네이티브 앱. 로컬 개발계획·FSD 규칙에서 RN/Expo로 기술. 원격 본문 조회 실패로 최신 구현 미확인 |
| `zipboda-api` | 서비스 데이터 제공. 조직에서 저장소 존재 확인, 최신 내부 구현 미확인 |
| `zipboda-admin` | 공고·자산·콘텐츠·회원·운영 관리. 로컬 계획에서 역할 확인, 원격 최신 구현 미확인 |
| `zipboda-design-system` | 공유 토큰·UI 계약·React DOM UI. 공개 README에서 패키지 구조 확인 |
| `.github` | 조직 소개 저장소. 조직 페이지의 서비스 소개 확인 |

[디자인시스템 README](https://github.com/ZIPBODA/zipboda-design-system)는 `@zipboda/tokens`, `@zipboda/ui-core`, `@zipboda/ui`를 분리한다. 웹은 DOM UI를 소비하고, 네이티브 앱은 토큰·계약을 활용한다. 웹의 공용 진입점은 `src/shared/ui/index.ts`다.

## 3. 도메인과 사용자 흐름

아래는 요구사항·화면설계서의 서비스 정의다. 실제 연동 완료를 뜻하지 않는다.

| 영역 | 기능·흐름 | 현재 웹 진입점 |
|------|-----------|----------------|
| 홈 | 청약·평면도·가구 탐색 진입, PC 히어로와 모바일 프로모션·퀵메뉴 | `/`, `widgets/home` |
| 청약 | LH·SH·GH·IH 공고 목록·필터 → 상세·평형·일정 확인 → 기관 사이트 신청 | `/subscriptions`, `/subscriptions/[id]` |
| 관심·신청함 | 관심/구독 관리, 신청함은 사용자가 표시하는 상태 | `/my` |
| 평면도·3D | 청약 상세의 2D/3D 확인 → 전체화면 탐색·시점 전환, WebGL 미지원 처리 | `/subscriptions/[id]/floorplan`, `widgets/floorplan-viewer` |
| 가점 | 무주택 기간·부양가족·통장 기간 입력과 점수 표시·저장·공유 요구사항 | `/score`, `features/score` |
| 집구경 | 인테리어 영감 갤러리·공간 분류·상세 라이트박스·좋아요/스크랩 | `/inspirations` |
| 커뮤니티 | 목록·상세·작성·수정·댓글·좋아요 요구사항 | `/community`, `/community/[id]`, `/community/write`, `/community/[id]/edit` |
| 쇼핑 | 가구 목록·상세·옵션·수량·담기·장바구니 UI | `/shop`, `/shop/[id]`, `features/cart` |
| 마이페이지 | 나의 청약·찜·주문내역, 프로필 수정 | `/my`, `/my/profile`, `widgets/my-page` |
| 인증 | 로그인·가입·비밀번호 찾기/재설정 화면 | `/login`, `/signup`, `/password/find`, `/password/reset` |
| 공통 셸 | 헤더·검색·알림·프로필·푸터, 모바일 하단 5탭 | `app/layout.tsx`, `app/AppChrome.tsx`, 관련 widgets |

현재 정의서에서 청약은 **외부 기관 신청 안내**다. 내부 신청 위저드, 독립 평면도 라이브러리·비교, 별도 쇼룸·방문예약은 제거/통합된 범위다. 결제·주문완료 화면은 추후·미설계로 기록되어 있다. 조직 소개만 보고 이 기능을 복원하지 않는다.

비회원은 열람, 회원은 관심·저장·작성 등의 보호 기능을 사용하는 구상이다. 운영자·관리자는 별도 운영 콘솔을 사용한다. 이 문서는 실제 인증·권한 보장 여부를 검증한 결과가 아니다.

## 4. 코드에서 확인한 상태

조사 기준 HEAD는 `c1c8f44`이며, 시작 브랜치는 `feat/floorplan-tracer`였다. 이 문서의 브랜치·구현 상태는 조사 시점의 스냅샷이다.

- `package.json`: Next.js `^14.2.15`, React `^18.3.1`, Tailwind `^3.4.14`, TypeScript `^5.6.3`, pnpm 10.27.0. 이는 선언 범위이며 정확한 설치 버전은 lockfile/설치 패키지로 재확인한다.
- three.js·React Three Fiber·Drei와 OpenCV.js·Tesseract.js가 선언되어 있다. 평면도 뷰어·트레이싱/검수 관련 코드가 존재한다.
- `src/app/page.tsx`는 서버에서 홈 데이터를 조회하고, Mobile과 PC 컴포넌트를 `md:hidden` / `hidden md:block`으로 나눈다.
- `MobilePromoCarousel.tsx`는 `HOME_PROMO_SLIDES`를 소비한다. 4초 자동 전환·도트 선택·카운터 코드가 있고, 배너 콘텐츠는 임시 데이터다. 현재 열려 있다는 사실만으로 수정 대상으로 삼지 않는다.
- `entities/*/api`와 `widgets/my-page/api`의 주요 조회는 `__mocks__`를 참조한다. 인증 화면에도 미연동 TODO가 있다. 화면 존재와 실제 서비스 연동 완료를 구분한다.
- 청약 목록의 지도 전환은 `/subscriptions?view=map`으로 동작한다. 지도는 카카오맵이며 `shared/ui/map`의 `MapViewLoader`가 유일한 진입점이다. `NEXT_PUBLIC_KAKAO_MAP_APP_KEY`가 없으면 스크립트를 주입하지 않고 카카오맵 링크 대체 표시로 간다. 좌표는 `shared/api/housing-data/geocode.json`에 따로 두며, 비어 있으면 지도 자리는 대체 표시가 된다. 전체화면 평면도 라우트와 `FloorplanExperienceLoader`의 CSR 동적 로딩은 구현되어 있다.
- `AppChrome`은 전체화면 평면도 경로에서 공통 셸을 숨기고, 일반 모바일 화면에서는 고정 하단 탭 여백을 제공한다.
- 모바일 하단 탭은 현재 코드상 **홈·청약·쇼핑·커뮤니티·마이페이지**다.
- `page.dev.tsx`는 `next.config.mjs`에서 개발 서버에만 등록한다. `/dev/floorplan-review`와 `/ds-check`는 일반 사용자 운영 화면과 구분한다.

## 5. 반응형·디자인 기준

- 현재 경계: Mobile ≤767px, PC ≥768px. 기본 스타일을 Mobile로 두고 `md:`에서 PC를 적용한다. 요구사항의 768px 검증은 포함하되 별도 태블릿 제품/레이아웃을 추가하지 않는다.
- 기준 검증 폭은 요구사항의 360·768·1280px와 분기 직전 767px다. 긴 텍스트·스크롤 레일·고정 탭·모달·뷰어의 가림/넘침을 확인한다.
- 구조가 다른 영역은 별도 Mobile 컴포넌트, 동일 구성의 간격·열 수 등은 기존 반응형 유틸을 따른다. 실제 디자인 확인 없이 전 화면 공통화하지 않는다.
- 디자인 토큰: 브랜드 앰버, Pretendard, 공통 의미색·간격·타이포. 세부 값은 `docs/ZIPBODA_design-system.md`와 설치된 토큰을 대조한다.
- 현재 홈 코드의 PC 출처는 `411:146`, Mobile은 `419:10637`, 캐러셀은 `419:10668`이다. 이는 코드/색인 확인 결과이며 이번 조사에서 Figma 실시간 렌더를 검증한 것은 아니다.

## 7. 조사 범위와 재확인

GitHub 조직 소개, 공개 web/디자인시스템 페이지, 로컬 `.claude` 규칙 11종, 개발계획·인수인계·디자인 색인, 요구사항/화면 xlsx, 라우트·주요 구현을 조사했다. 인터페이스 xlsx는 구조와 시트 구성을 확인했으며 현재 화면 작업 범위에 맞춰 상세 설계로 확장하지 않았다.

원격 app/api/admin 본문은 조회 실패로 최신 소스를 확인하지 못했다. Figma 실제 노드·전 화면 브라우저 동작·운영 데이터·배포 환경도 이번 조사에서 검증하지 않았다. 따라서 서비스 전체 비전과 로컬 구현 맥락을 정리한 것이며, 모든 저장소·기능의 검증 완료를 의미하지 않는다.

작업 재개 시 관련 코드·문서·실제 디자인을 다시 확인하고 이 기록과 차이가 있으면 근거와 함께 갱신한다. 요구사항/화면 정의를 대신하는 새로운 정본으로 사용하지 않는다.
