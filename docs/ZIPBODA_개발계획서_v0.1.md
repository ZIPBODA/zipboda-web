## 2. 개요

### 2.1 목적
본 문서는 집보다 **사용자 PC 웹(`zipboda-web`)**의 개발 계획을 정의한다. 요구사항·화면·API 정의서(zipboda-web 대표 관리)를 근거로, 웹이 구현·소비하는 요구사항ID·화면ID(ZB-U-*)·API ID를 추적한다.

### 2.2 서비스 개요
LH·SH·GH·IH 공공 청약 정보 통합 조회 + 평면도(2D)·**WebGL 3D 배치도(1·3인칭 집구경)** + 인테리어 영감·쇼룸·가점·커뮤니티·마이페이지. 2차로 가구 커머스.

### 2.3 범위 / 저장소 매핑
`zipboda-web` = 사용자 PC 웹 화면 전체(ZB-U-*). 모바일=`zipboda-app`, API=`zipboda-api`, 관리자=`zipboda-admin`.

| 저장소 | 역할 | 비고 |
|--------|------|------|
| **zipboda-web** | 사용자 PC 웹 | **본 문서 대상 / xlsx 3종 대표 관리** |
| zipboda-app | 사용자 모바일 앱 | 동일 도메인, 모바일 UX |
| zipboda-api | 백엔드 API | 웹 소비 API 제공 |
| zipboda-admin | 운영 콘솔 | 운영 데이터 관리 |

## 3. 기술 스택 및 주요 결정 (권장, 착수 승인 필요)

> 검토 결함 C2(스택 미확정) 반영. 아래는 **권장 확정안**이며 킥오프에서 최종 승인한다.

| 항목 | 결정(권장) | 근거 |
|------|-----------|------|
| 프레임워크 | **Next.js(App Router) + TypeScript** | 청약 정보 SEO·공유·초기 로딩(검토 web-Major: SSR/SEO) |
| 렌더링 전략 | 청약 목록/상세=**SSR/ISR**, 3D 뷰어·마이·커머스=**CSR** | SEO 필요 영역만 서버 렌더, 인터랙션 영역은 클라이언트 |
| 폴더 구조 | Feature-Sliced Design | frontend-architecture.md |
| 서버 상태 | TanStack Query(응답 `{success,data,error}` 소비) | — |
| 3D 엔진 | **three.js + glTF/GLB(Draco 압축)** | ZB-U-PLAN-04, REQ-CO-005 |
| 공유 코드 | **pnpm workspace `@zipboda/shared`**(API 타입·훅) app과 공유 | 검토 app-Minor(공유 메커니즘) |

### 3.1 디자인시스템 토큰(Figma)
Brand `#FFBA17` / Neutral `#111111`~`#F3F4F6` / Semantic 정보 `#2B7FFF`·성공 `#00BC7D`·경고 `#F59E0B`·오류 `#FF6467` / Social Kakao `#FEE500`·Naver `#03C75A` / Pretendard, weight 400–900, scale 10~48.

### 3.2 WebGL 3D(집구경)
평면도 3D 배치도(ZB-U-PLAN-04)를 three.js로 구현. 자산 메타 API-032 로딩, 1·3인칭 전환(ITF-013)·이동·회전, 미지원 시 2D 폴백(ZB-U-PLAN-03). 성능 목표 30fps 이상(REQ-NF-003).

## 7. 일정·공수 요약

- 총 공수(web): 약 **32.5 PW** (2차 커머스 5 PW 포함). 인력 가정: FE(web) 2명 + 3D 0.5명.
- **크리티컬 패스:** S1 인증 → S2 청약(SSR) → **S4 평면도 3D** → S7 안정화. S4는 최대 리스크로 S2 착수 시 3D 스파이크(PoC)를 병행한다.
- app과 `@zipboda/shared`로 API 타입·훅을 공유하여 W2~W8 중복 공수를 절감(소유권: 타입은 api 생성물 기준).
