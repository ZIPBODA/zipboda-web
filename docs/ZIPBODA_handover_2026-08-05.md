### 선택지

- **A. 화면별 모바일 컴포넌트 신설 + 분기 렌더** — 디자인 100% 충실. 컴포넌트 수 약 2배, 두 트리가 마크업에 모두 포함. **권장**
- **B. 공통 컴포넌트에 반응형 배리언트 추가** — 코드 재사용에 유리하나 제목·퀵메뉴 항목 등이 디자인과 달라져 `frontend.rule.md` A2(임의 축소·합침 금지) 위반 소지
- **C. 절충** — 레이아웃·간격은 `md:` 유틸, 구성이 다른 부분만 분기. 경계가 모호해 화면마다 판단이 흔들릴 위험

A를 택하면 **화면 1개 = PR 1개**로 진행해야 리뷰 가능한 분량이 유지된다.

## 6. 반드시 알아야 할 함정

### 6.1 `.mcp.json`·`.npmrc` 커밋 금지

두 파일은 **tracked 상태이며 워킹트리에 실제 토큰이 평문으로 들어 있다.** 커밋본은 `${ENV}` 참조라 안전하다. `git add -A`·`git commit -a`로 딸려 들어가지 않게 커밋 전 `git status`를 확인한다.

원격에서도 정리하려면 저장소별 `git rm --cached` + `.gitignore` 등록이 필요하다(미실행). 또한 `.env` 파일이 없고 환경변수도 비어 있어, `${VAR}` 치환이 동작하려면 **프로세스 환경변수**가 필요하다(`.env` 파일만 만들어도 MCP·pnpm은 읽지 않는다).

```powershell
setx FIGMA_API_KEY "figd_..."      # Figma 개인 토큰(figd_ 접두)
setx NODE_AUTH_TOKEN "ghp_..."     # GitHub Packages read:packages
# 이후 터미널·VS Code·Claude Code 완전 재시작
```

### 6.2 dev 서버 중복 — 반드시 단일 3000

`⚠ Port 3000 is in use, trying 3001` 가 뜨면 **우회하지 말고** 기존 서버를 정리한다. 옛 서버(옛 코드)를 보며 "안 고쳐졌다"고 오인하는 사고가 이미 기록되어 있다(`visual-verification.rule.md` C2).

`TaskStop`으로 래퍼만 죽여도 **자식 프로세스(next dev·next-server)가 살아남아** `.next`를 잠근다. 그 상태로 `pnpm build` 하면 `EPERM: .next/trace`로 실패한다.

```powershell
Get-CimInstance Win32_Process -Filter "Name='node.exe'" |
  Where-Object { $_.CommandLine -match 'next|pnpm.js dev' } |
  ForEach-Object { Stop-Process -Id $_.ProcessId -Force }
Remove-Item .next -Recurse -Force
```

### 6.3 시각 검증은 클래스 문자열만 보지 말 것

브라우저 자동화 도구가 없어 V1 대체 절차(서빙 DOM 대조)로 검증하고 있다. 다만 **클래스가 붙어 있어도 CSS가 생성되지 않으면 무효**다. 반응형은 생성된 스타일시트에서 규칙까지 확인한다.

```
기본 .hidden            → display: none
@media (min-width:768)  → .md:block / .md:absolute / .md:hidden
```

또 React가 보간값과 리터럴 사이에 주석 노드(`<!-- -->`)를 넣어 `1,280,000원` 같은 문자열 매칭이 실패한다. 검증 시 `-replace '<!--.*?-->',''` 로 제거하고 비교한다.

### 6.4 xlsx 정의서 읽기

`docs/`의 정의서 3종은 xlsx다. 로컬 Python에 **openpyxl이 없어** `zipfile` + `xml.etree`로 직접 파싱해야 한다. `xl/_rels/workbook.xml.rels`의 sheet Target에 이미 `xl/` 접두가 붙은 경우가 있어 경로를 그대로 이어붙이면 `xl/xl/...`로 KeyError가 난다. 파서 스크립트는 저장소 밖(TEMP)에 만들고 작업 후 삭제한다.
