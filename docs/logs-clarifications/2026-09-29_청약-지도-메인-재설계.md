## 3. 원래 지시
- 청약 페이지의 메인이 목록이 아닌 지도였으면 좋겠음
- 위와 관련하여 UX 적으로 재설계 요청

## 4. 모호한 부분
"UX 적으로 재설계"의 범위와 기준이 없다. 지도를 메인으로 두면 흐름이 갈리는 네 지점을 특정했다.
- PC 첫 화면에서 목록 패널을 펼칠지(당시: 닫힘, 버튼·배지·핀으로 열기)
- 모바일에서 목록을 어떻게 여는지(당시: '청약 N' 버튼 → 반 높이 시트)
- 상세에 다녀온 뒤 지도를 복원할지(당시: 매번 공고 전체에 다시 맞춤)
- 목록 보기로 들어가는 길(당시: 목록 화면 '목록 | 📍 지도' 세그먼트, 지도 툴바 '목록' 링크)

## 5. 에이전트 질문
1. PC 첫 화면: 지도 영역 목록 펼침 / 지금처럼 닫힘
2. 모바일: 하단 시트 상시 노출 / 지금처럼 버튼
3. 돌아오기: 보던 지도 그대로(URL 보존) / 처음 화면으로
4. 목록 보기: 전환 버튼 통일(지도 먼저) / 목록은 보조 링크로만

## 6. 사용자 응답
1. 지도 영역 목록 펼침
2. 하단 시트 상시 노출
3. 보던 지도 그대로
4. 전환 버튼 통일

## 7. 확정된 규칙
- `/subscriptions`의 기본 보기는 지도다. 목록은 `?view=list`, 예전 `?view=map` 링크도 지도로 연다.
- PC: 왼쪽 패널이 처음부터 열려 있고 지금 지도에 보이는 청약을 보여주며 지도를 움직이면 따라 바뀐다. 배지·핀을 누르면 그 묶음으로 좁혀지고 '지도 영역 전체 보기'로 되돌아간다. 공고 상세를 연 동안에는 목록을 고정해 카드가 사라지지 않게 한다. '청약 N' 버튼은 패널 접기·펴기다.
- 모바일: 지도 아래 시트가 늘 보이고 손잡이에 건수를 표시한다. 누르면 반 높이·접힘을 오가고, 끌면 반·전체 높이로 맞춘다. 배지·핀을 누르면 반 높이로 펼친다.
- 지도 중심·확대 단계를 `lat`·`lng`·`zoom` 쿼리로 보존한다. 뒤로가기·새로고침·공유 링크에서 같은 지도가 열린다. 공고 상세의 '목록으로 돌아가기'도 마지막으로 보던 지도·목록 주소로 돌아간다.
- 지도·목록 화면 모두 같은 '📍 지도 | 목록' 전환을 쓰고 지도를 먼저 둔다. 상단 메뉴·하단 탭·홈 '전체 보기'는 모두 지도로 간다.
