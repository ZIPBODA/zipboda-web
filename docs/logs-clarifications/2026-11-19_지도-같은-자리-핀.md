## 3. 원래 지시
- 권장 순서대로 작업 요청 — A3 "지도 핀(미결 6): 같은 단지가 여러 공고에 나와 핀이 겹칩니다(핀 1,324개, 응답 771KB). 단지 단위로 합치거나 영역별로 받기"

## 4. 모호한 부분
- "단지 단위로 합치거나 영역별로 받기" — 겹친 핀을 화면에서 어떻게 보여 줄지(묶음 배지·펼치기·이름표 문구)와 응답 크기 대응(전체 한 번에 받기 유지·영역별 조회)이 정해지지 않았다.
- 실데이터(2026-11-19): 좌표 있는 칸 1,087개 중 297개가 121곳에서 좌표가 완전히 같다(한 곳 최대 12개, 좌표가 같으면 모두 같은 단지). 가장 가까운 단계(1)는 묶지 않아 핀이 한 자리에 포개지고 맨 위 하나만 눌렸다. 응답은 658KB(gzip 103KB)·0.14초.

## 5. 에이전트 질문
1. 가장 가까운 단계에서 포개진 핀을 어떻게 보여 줄까? ('N건' 배지로 묶기 / 동그랗게 펼치기 / 핀 하나 + '외 N건' 이름표)
2. 응답 크기 대응은? (지금처럼 전체 받기 + API 파라미터 상한만 없애기 / 영역별 조회로 바꾸기)

## 6. 사용자 응답
1. 'N건' 배지로 묶기
2. 지금처럼 전체 받기

## 7. 확정된 규칙
- 가장 가까운 단계(`MAP_DETAIL_PIN_LEVEL`)에서도 묶음을 켜고 격자를 `MAP_SAME_SPOT_GRID_SIZE`(1px, 약 0.25m)로 좁힌다 — 같은 자리 핀만 다른 단계와 같은 'N건' 배지가 되고, 누르면 옆 목록에 그 공고들을 보인다. 따로 선 핀은 지금처럼 이름표를 단 핀이다.
- 2026-09-29 규칙 "여러 건이 겹친 묶음은 갈라질 때까지 배지로 남는다"와 같다 — 같은 자리 묶음은 끝까지 갈라지지 않는다.
- 지도는 조건에 맞는 핀을 영역 없이 한 번에 받는 방식을 유지한다. API는 핀 id를 다시 읽을 때 배열 파라미터 하나를 써 PostgreSQL 바인드 파라미터 상한(65,535)을 없앤다(zipboda-api ERD 미결 6).
