## 3. 원래 지시
- 현재 청약 목록 지도 페이지의 렌더링 속도가 굉장히 느린 것으로 확인됨. 전체 페이지 확인하여 렌더링 속도 개선 요청
- core web vital 기준으로 작업을 E2E, QA를 진행할 것

## 4. 모호한 부분
- CLS를 '좋음'(0.1 이하)으로 맞추려면 공고를 열 때 지도가 날아가는 애니메이션(0.7초)을 줄여야 했다 — 사용자 경험(움직임 속도)이 바뀐다. 0.5초를 넘기는 동안 움직이는 지도 조각을 CWV가 레이아웃 이동으로 센다(데스크톱 CLS 0.62, 0.45초로 줄이면 0.015).
- 남은 큰 병목(카카오 클러스터러: 핀 수만큼 강제 레이아웃, 모바일 1.3초 긴 작업 → 로드 TBT 1.27초·확대 INP 624ms)을 없애려면 지도 핀 레이어를 다시 써야 했다 — 작업 범위가 커지고 커밋 대기 중인 A3(같은 자리 핀 배지)와 같은 파일을 고친다.

## 5. 에이전트 질문

## 7. 확정된 규칙
- `MAP_FOCUS_ANIMATION_MS = 450`. 누른 뒤 0.5초 안에 날아가기가 끝난다(내 위치로 갈 때도 같은 속도).
- 지도 묶음은 카카오 MarkerClusterer와 같은 규칙(가장 가까운 묶음·격자 사각형·평균 중심, 확대·축소하면 처음부터, 옮기면 새로 들어온 집만)으로 직접 계산하고(`markerClusters.ts`), 배지는 묶음마다 한 번 그린다. clusterer 라이브러리는 받지 않는다.
- A3(가장 가까운 단계에서도 같은 자리 핀은 'N건' 배지)는 이 계산 위에서 그대로 지키고, 이 PR에 함께 들어간다. 화면 밖으로 미리 묶어 두는 여유 폭은 격자와 따로 80px로 둔다(A3 검토에서 남긴 '가장 가까운 단계에서 끌면 핀이 손을 뗀 뒤 나타남' 절충을 없앤다).
